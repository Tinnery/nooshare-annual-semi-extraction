## 一、步骤 1：冻结库

### 数据结构

每条组合包含：
- `confirmed_by`：确认主体、来源、时间、`human_confirmed`、`human_review_required`
- `legal_basis`：法规原文 PDF 的 sha256 + 文号 + 施行日 + 命中的具体节（含 `required`）
- `near_miss`：从 `h1_combo_audit.json` 被拒组合中取最相似的 1–2 条，附拒绝理由
- `fingerprint` / `exact_key`：判定键
- `impurities`：如实标出残留噪声

### 如实标注，不伪造

| 项 | 值 |
|---|---|
| 带 `legal_basis` 的组合 | 27 / 27 |
| 带 `near_miss` 的组合 | 27 / 27 |
| `human_confirmed = true` | **0 / 27** |
| 含 `impurities` 的组合 | **8 / 27** |

原 `h1_clean_combo_template.json` 的 27 条是**规则脚本审核**产物，不是人类逐条确认。
冻结库明确写 `human_confirmed: false` / `human_review_required: true`。
按 M1/M2，人工确认闭环前不得声称「已确认」。

8 条残留噪声包括：`释义在本报告书中`、`优先股相关情况报告期公司不存在优先股`、
`财务报告审计报告`、`释 义`（内部空格）等。这些在原审核里被判 `valid`，实际是粘连噪声，
本次逐条记入 `impurities`，未假装干净。

### 法规锚定

- 权威：证监会公告〔2021〕15号（年报第2号）/〔2021〕16号（半年报第3号）正文十节
- 原文 sha256 取自 `regulatory_versions.json`，例如 15号 `b727419bdab8b137…`
- **「备查文件目录」不是法定正文十节**，仅作前后置节处理（此前根因审计已纠正 11 项分母错误）
- 第 8/9 节为 `conditional`（发行优先股/债券才须披露）

### 冻结库 sha256

```
f81f579a7ca41338e298f037fb9166831c27ff18752ddd648235ae1daea96e3d
```
登记于 `data/h1_frozen_library_sha256.txt`；判定模块加载时强校验，不符即拒绝启动。

## 二、步骤 2：提取器加载冻结库

### 判定规则

| verdict | 含义 |
|---|---|
| `freeze_hit_exact` | 规范化标题序列精确命中某条冻结组合 |
| `freeze_hit_signature` | 命中冻结组合的法规十节指纹（确定性选唯一代表组合） |
| `known_failure` | 未命中，但接近冻结库记录的 near-miss 反例 |
| `residual` | 未命中 → 落残差，进入第二轮积累 |

签名命中时用「文本相似度 → 组合 count → combo_id」三级确定性排序选唯一代表，
避免罗列 22 个候选导致判定无区分度。

### 跨版本对齐（关键根因）

冻结库 27 条来自**旧版提取器**，其 `canonical_cats` 与当前 `h1_full.jsonl`（v2_reg_anchored）
**不兼容**：直接按类别序列精确匹配只能命中 **284 份（0.74%）**。

修复：判定键改用**法规十节指纹**（规范化标题 → 映射到法定节号 + 非法规节集合），
两个体系都映射到同一个外部锚。27 条组合坍缩为 **4 个唯一指纹**，全量命中率 91.39%。
指纹函数由构建脚本与运行时判定程序共用同一实现（`h1_frozen_judge.py`），杜绝期际漂移。

### 零回归设计

`h1_extractor.py` **只追加 `frozen_verdict` 字段，不改任何既有字段**。
提供 `--no-frozen` / `H1_FROZEN_EMIT=0` 开关，用于逐字节对比。


### 拦住了一个会污染冻结库的错误

若按频次直接把残差最高频组合入冻结库，Top1 是 `{"sections":[1],"extras":[]}`——
**786 份只有第一节的单节碎片**。这属于提取失败，不是合法组合。
按 U-H1.3「频次只作候选排序，不作正确性裁判」，必须先分级。

### 残差分级结果

| 类别 | 报告数 | 唯一指纹 | 处置 |
|---|---|---|---|
| `ELIGIBLE` 十节齐全无额外节 | **36** | **1** | 进第二轮确认队列 |
| `VARIANT` 十节齐全但有额外节 | 384 | 123 | 人工判断额外节合法性（A+H 的监事会报告等） |
| `FAILURE` 碎片/缺失/空 | 2,883 | 342 | 进故障归因，**不得入冻结库** |

唯一 ELIGIBLE 候选：`{"sections":[1,2,3,4,5,6,7,8,10],"extras":[]}`（缺第 9 节债券，36 份），
边际新增覆盖 **0.094%**。

**这是积累饱和的真实信号**：27 条冻结组合已覆盖绝大多数合法结构，残差主要是提取失败
（版式异常、A+H 变体、MD 残缺），不是「还缺 pattern」。继续扩库是「更大版本」，
正确动作是**修提取器 / 归因故障**，而不是补充组合。

`md_h1` 提取路径，而非组合库缺失。

## 四、步骤 4：只读回放零回归

分层抽样（year × period × method × verdict，38 桶，每层 ≤12 份，固定种子 20261114），
对每份 MD 分别以 `H1_FROZEN_EMIT=1/0` 真实重跑 `extract()`：

| 检查 | 结果 |
|---|---|
| 抽样桶 / 抽中 / 实测 | 38 / 364 / 364（无缺失 MD） |
| baseline 既有字段 sha | `6aff5fd4…0fa5` |
| 加载冻结库后 sha | `6aff5fd4…0fa5` |
| **逐字节 diff** | **0 → PASS** |
| 判定可复现 | 364 检查，0 不符 → PASS |
| 命中集 sha 复算 | 与登记一致 → PASS |

证据：`data/frozen_zero_regression.json`。

### 顺带澄清了长期口径矛盾

第一步复算曾 FAIL，根因是步骤 4 用 dict 存 replay 结果触发去重：
**38,350 行里只有 36,899 个唯一 slot，1,451 个 slot 重复**（同一 slot 有多份 MD 来源）。
这正好解释历史上 38,350 / 36,899 / 36,806 三个分母并存的由来。
修正为按原始 jsonl 行级重算后 PASS；报告同时登记行级与唯一 slot 两个口径。

## 六、仍未闭环（须明确）

1. **人工确认未做**：27 条均为规则脚本审核，`human_confirmed = false`。
   按原策略「经 agent 或人类确认」，需人工逐条复核 27 条 + 8 条噪声残留后才能声称闭环。
2. **组合库只是判定层，不是提取规则**：本次让冻结库成为判定依据，但识别仍由
   `h1_extractor` 的法规锚定逻辑完成。若原意是「组合库直接驱动提取」，还需改造提取阶段。
3. **`freeze_hit_exact` 仅 8 份**：91.39% 命中靠 4 个宽签名，组合语义被稀释。
   如需更严格判定，应引入更多可确认组合或收紧指纹粒度。
4. **残差 2,883 份是故障，不是待积累 pattern**：应转向提取器修复与故障归因
   （`md_h1` 层 0% 命中、2021 半年报 68.4%），而非继续扩库。
5. **冻结库未入 PG**：目前是文件态。若需作为生产判定程序，须登记到 01 §〇 sha 并纳入五元锚。

## 七、结论

按用户指定的四步顺序全部落地并验证：冻结库建成、提取器加载、全量回放、
零回归 PASS。过程中拦住了「按频次把 786 份碎片当合法组合入库」的污染风险，
并澄清了 38,350 / 36,899 的口径矛盾（1,451 个重复 slot）。

**最重要的结论不是覆盖率，而是饱和信号**：残差 3,303 份里只有 36 份是合法结构变体，
其余 98.9% 是提取失败。继续「积累组合」是错误方向，下一步应修提取器与故障归因。
人工确认闭环仍未完成，报告中未声称「已确认」。
