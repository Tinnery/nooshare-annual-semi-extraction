# 编号组合提取：更深版本（四段式回答 + 需求重写）

> Date: 2026-11-13 · **Status: 分析归档（Authority: 无）** · 唯一需求权威仍为 `01-requirement.md`（v2）
> 触发：用户「不能提取组合吗：1. 2. 3. 4. 作为一组，然后优先分析匹配数最高的那组，而且要全量提取」
> 关联：`10`（不需要标题识别能力）、`11`（形态修正）、`08/09`（已标注为条件性方案）
> 脚本：`scripts/numbering_combos.py`、`fetch_all_md.py`、`verify_numbering_spans.py`
> 数据：`data/numbering_combos.json`（全量）、`data/numbering_combos_smoke.json`（200 份方法验证）

## 短答

**能提取，而且你的切入点（把连续编号当一组）比逐行判标题更对**：单个 `1、` 无法判层级，但**连续 `1,2,3,…,10` 序列本身是结构信号**，且可用编号重置无监督切分。

**但"优先分析匹配数最高的那组"必须改**：实测最高频组合是 `AR_PAREN:1,2`（4,381 次，200 份样本），法定节名命中率 **0.02**，是财报附注的三级子项；而按法规对齐度排第一的 `CH_ZH:1,2,…,10`（185 次）命中率 **0.995**、恰好等于〔2021〕15/16 号的法定 10 节。

> 序列模式挖掘的已知陷阱：**子序列频次随长度单调递减**，纯频次贪心必然选中最短、最无信息量的模式。频次是**排序信号**，不是**筛选信号 / 正确性裁判**。

**正确顺序**：全量候选生成 → 编号重置切 run → **外部锚先筛选**（法定节数 + 节名命中 + md 层级）→ 合格候选内再按频次排序。200 份验证：550 种组合收敛到 **3 种**，覆盖 **92.5%** 报告。

## 一、顶尖专家会采取、而前几轮（含 06/09/10/11）没想到的做法

1. **短模式支配（short-pattern dominance）**：任何序列模式集合里，长度 2 的子序列频次天然高于长度 10 的完整序列；不按长度归一化或按信息量加权，"最高频"恒等于"最短"。这是 MDL / 序列模式挖掘的基本结论，前几轮只说了「频次被模板绑架」，没指出这个**结构性单调偏差**。
2. **编号重置检测**：连续编号回到 1（或下降）即层级边界，无需任何标注即可把"一级章节序列"与"章节内子项列表"切开。实测 **100% 报告存在同体系多 run**，说明这是普遍且可用的信号，而非边缘情况。
3. **法规节数作为长度先验（不从数据学）**：`reg_version → legal_chapters.json` 直接给出法定节数（〔2016〕31号 12 节、〔2021〕15/16号 10 节、〔2025〕3/4号 8 节）。组合长度是否合格**由法规给定**，不需要 Chao1、不需要饱和曲线、不需要 AGENT。这比 09 用物种丰富度估"还有多少种"深一个层级。
4. **外部锚前移为筛选器**：前几轮把法规放在"裁判四层"的最外层（事后验证）；专家会把它放在**候选生成之后、频次排序之前**，让 99% 噪声根本不进排序池。裁判与筛选是两个位置，不是同一件事。
5. **多编号体系等价类显式化**：`第X章` / `第X节`、`一、` / `1.` / `（1）`、全半角、中文/阿拉伯数字，哪些等价、哪些不等价必须版本化定义；否则同一结构被拆成多个稀疏组合，频次被稀释。
6. **层级由多信号联合推断**：`md_level`（# 个数）+ 编号体系 + run 长度 + 法定名命中率，四者交叉验证，不靠单一正则。实测 `md_level=(0,)` 的长 run 全是财报附注，`md_level=[1]` 且长度 10 的全是一级章节——判别力来自联合，不来自任一单信号。
7. **负对照组**：把「长度 ≥8 但 `md_level=0`、法定率 0.0」的财报附注长列表显式作为负样本，验证筛选器不误收。前几轮只做正例统计，没有负对照。
8. **跨 (year, period) 组合稳定性**：`CH_ZH:1..10` 在全部 8 个层稳定出现（19/22/23/22/24/24/23/22），才能排除"某模板厂偶然"；总频次高不等于结构稳定。
9. **有序 vs 无序组合分离**：`1,2,3,4` 序列与 `{1,2,3,4}` 集合语义不同，E1 的 `order` 判定需要前者。组合单位必须显式声明。
10. **全量提取 ≠ 全量验证**：用户要"全量提取"是对的（候选生成，01 §五.3 不禁止）；但验收仍须分层判别对，不能用全量覆盖率宣称结果正确。

## 二、未经加工的原始数据 / 具体工具 / 专业方法

### 2.1 原始数据（回到字节，不用已加工产物）

| 数据 | 为什么必须是未加工形态 |
|---|---|
| RustFS `published/*.md` **原始字节的每一行** | 编号行可能是 `md_level=0` 的纯文本行（财报附注），只扫 H1/H2 会漏掉负样本；`11` 的 `heading_corpus.jsonl` 只存了 H1，不够用 |
| 行首编号的**物理形态**：`1、` `1.` `（1）` `一、` `第X章`、全半角数字、Wingdings 残留 | 决定编号体系等价类；清洗掉就丢了判别信号 |
| 编号的**重启位置**（行号 + byte offset） | 编号重置检测的输入，可回放 |
| 交付表 `winner_md_path` / `content_sha256` / `fingerprint` / `winner_source` / `selection_rule` / `candidate_count` | 模板族去冗余与分层 |
| `legal_chapters.json` 各版本 `sections`（含 `required`） | 法定节数与节名，外部长度先验 |
| `regulatory_versions.json`（`by_period_end`） | 决定每份报告用哪一版节数 |
| 上游 `reference/report_patterns.json` canonical 变体 | 59 条有限集，用于节名命中率 |

### 2.2 工具（零新增依赖）

- 纯标准库：`re`（只做候选生成，不作层级判定）、`hashlib`、`collections`、`json`、`concurrent.futures.ThreadPoolExecutor`（全量下载并行，单 boto3 client 复用）
- `boto3` + `botocore.Config(max_pool_connections=32)`（RustFS GET，01 §四授权）
- 只读复用上游（铁律 4）：`_map_heading_to_category`、`slot_key`、`CHINESE_NUM_MAP_ENHANCED` 语义、`report_patterns.json`
- `pytest` 属性测试 / 独立校验脚本：verbatim 回放、编号连续性、长度先验一致性

### 2.3 专业方法

编号体系归一化（cn/ar、章/节、全半角、括号）· **编号重置检测** · run 切分 · 多信号层级推断 · **法规节数长度先验** · 法定名最长前缀命中率 · **外部锚筛选 → 频次排序** · 长度加权/MDL 对照排名 · **负对照组** · 跨 (year,period) 稳定性 · verbatim byte offset 回放 · 全量候选生成 + 分层抽样验收。

## 四、重写后的需求 U-C1 – U-C8

> 沿用 R'0-R'9 / E1-E6 / M1-M3，**不新增 Requirement 代际、不新增 E 编号、不新增依赖**（01 §七）。
> 与 `10` 兼容：编号组合是**结构指纹 / EXTRACTION_FAILURE 诊断**，**不是** E1 完备性判定的输入。

| # | 需求 | 绑定锚 | 可机器校验产物 |
|---|---|---|---|
| **U-C1** | 定义**编号体系等价类**与**组合单位**（有序序列），版本化为 `combo_scheme=v1`；明确 cn/ar、章/节、括号、全半角哪些等价 | M1 / M3 | 等价类表 + `combo_scheme` |
| **U-C2** | **全量候选生成**：对论域内每份 MD 的**所有行**（不限 H1）提取编号行，记录 line / byte offset / verbatim / md_level。**此阶段不判任何正确性** | M2 / 01 §五.3 | 全量编号行清单 + sha |
| **U-C3** | **编号重置检测**：同体系内 ordinal 下降或回到 1 即切新 run；每个 run 记 ords、names、首末 offset、层级集合 | 编号连续性 | run 清单，`ords` 严格连续 |
| **U-C4** | **外部锚筛选器**（在频次之前）：`reg_version → N`；候选 L1 须同时满足 ① `contiguous_from_1` ② `abs(len-N) <= 2` ③ `md_level` 全为 1 ④ 法定名命中率 ≥ 0.5。四条均可外部复核 | E1 / M2 | 候选集合 + 每条的四项证据 |
| **U-C5** | **筛选后才按频次排序**；同时输出「纯频次 / 法规对齐度 / 长度加权」三套排名作对照。**禁止**以原始频次作为正确性裁判 | M1 | 三套排名 + 差异说明 |
| **U-C6** | **负对照组**：把长 run 但 `md_level=0` / 法定率 0 的财报附注列表显式登记为负样本，验证 U-C4 无误收 | R'1⑥ | 负例集 + 误收率 |
| **U-C7** | **分层报告**：按 (year, period, source) 给出候选组合覆盖率、跨公司/跨年/跨期复现度、残差集；不得只报总频次 | 01 §五.2 / E5 | 分层矩阵 + 残差清单 |
| **U-C8** | **可回放与停止**：verbatim byte offset 回放校验进 CI；停止判据用上游 S-3 `monotonic_check`，全量只证明"没崩"，验收走分层判别对 | M2 / M3 / E4 | `pytest` 属性测试 + `monotonic_check` |

### 触发条件（沿用 `10` §五）

只有在「A：字数列成硬验收 / B：二期 research repo 真消费章节级特征 / C：extra·order 写入 E1 pass_condition / D：需要章节级 `semantic_path`」之一成立时，U-C 才从"诊断"升级为"主链路"。当前**全不成立**，故 U-C 产物为 advisory。
